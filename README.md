# Anime Recommender — LLMOps on Kubernetes

> **Source & Credits**: Based on [data-guru0/ANIME-RECOMMENDER-SYSTEM-LLMOPS](https://github.com/data-guru0/ANIME-RECOMMENDER-SYSTEM-LLMOPS), customized for this project.

An end-to-end **LLMOps** demo for anime recommendation. A **FastAPI** API retrieves similar titles from **ChromaDB** and asks **Gemini** to explain the picks; a thin **Streamlit** UI calls the API. It runs on **Amazon EKS** the way an SRE team would run it: SLOs with burn-rate alerts, canary releases with automatic rollback, autoscaling, load-tested capacity, and LLM tracing with token and cost metrics.

---

## ✨ Features
- **Gemini + Hugging Face embeddings + ChromaDB:** the index is built during the image build, and the build fails unless all 269 anime are present.
- **EKS** on a Spot node group, provisioned with **Terraform** and reconciled by **Argo CD**.
- **Argo Rollouts** canary (10% → 50% → 100%) gated by Prometheus analysis, with automatic rollback.
- **SLOs** generated by Sloth, with multi-window burn-rate alerts sent to Discord.
- **KEDA** scales the API on in-flight requests, not CPU.
- **OpenTelemetry** traces to Tempo and Langfuse, plus token and cost metrics per model.
- **GitHub Actions** with OIDC (no AWS keys), Trivy scanning and Cosign keyless signing.

## 🏗️ Architecture Overview
```
[User] ─> ALB (AWS Load Balancer Controller)
            ├─ /           ─> anime-ui  (Streamlit)  ──HTTP──┐
            └─ /recommend  ─> anime-api (FastAPI, Rollout) <─┘
                               ├─ stable + canary Services (weighted by the ALB)
                               ├─ Chroma index (baked into the image)
                               ├─ Gemini API · HF Inference API
                               └─ OTLP ─> OTel Collector ─┬─> Tempo
                                                          └─> Langfuse Cloud

[Monitoring]
  Prometheus <─ ServiceMonitor(api) ─ Sloth SLO rules ─> Alertmanager ─> Discord
  Argo Rollouts ─ AnalysisRun (success rate, p95) ─> promote | rollback
  KEDA ─ in-flight requests ─> scales anime-api (2–8 pods)

[Delivery]
  git push ─> GitHub Actions (test → build → Trivy → ECR → cosign → bump digest)
          ─> deploy/ in this repo ─> Argo CD ─> canary rollout
```

## 🐳 Run locally with Docker

The app is split into a **FastAPI recommendation API** (`services/api`) and a thin **Streamlit UI** (`services/ui`).

```bash
cp .env.example .env               # fill GOOGLE_API_KEY and HF_TOKEN
docker compose up --build -d       # API on :8000, UI on http://localhost:8501
curl -X POST localhost:8000/recommend -H 'content-type: application/json' \
     -d '{"query": "light hearted anime with school settings"}'
```

- **The index is built inside the image build.** The HF token is passed as a BuildKit secret and is never baked into a layer.
- **Fake provider** (no network, for load tests and failure drills): `LLM_PROVIDER=fake FAULT_RATE=0.2 docker compose up -d api`.
- **Lint + tests:** `docker build -f services/api/Dockerfile --target test .`

| API endpoint | Purpose |
|---|---|
| `POST /recommend` | `{query}` → 3 explained picks, retrieved titles, model, trace id |
| `/healthz`, `/readyz` | Liveness / readiness (index loaded and complete) |
| `/metrics` | Prometheus metrics (see cheat-sheet below) |

## ✅ Prerequisites
- **Tools:** AWS CLI v2, Terraform ≥ 1.10, kubectl with the Argo Rollouts plugin, Helm 3, Docker, cosign, k6, and the GitHub CLI (`gh auth login` first).
- **Accounts:** an AWS account with admin access, and admin rights on this GitHub repo.
- **Keys:**
  - a Gemini API key
  - a Hugging Face token with the *Inference Providers* permission
  - a Langfuse Cloud project (public + secret key)
  - a Discord incoming webhook for alerts

## 🔐 Environment & Secrets
Secrets live in **AWS Secrets Manager** and are synced into the cluster by **External Secrets**. Nothing secret is stored in Git.

| Secret | Keys | Used by |
|---|---|---|
| `anime/llm` | `GOOGLE_API_KEY`, `HF_TOKEN` | anime-api |
| `anime/langfuse` | `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` | OTel Collector |
| `anime/alerting` | `DISCORD_WEBHOOK_URL` | Alertmanager |

App settings are plain environment variables in the Helm values:

| Variable | Default | Description |
|---|---|---|
| `MODEL_NAME` | `gemini-3.5-flash-lite` | Gemini model |
| `LLM_PROVIDER` | `gemini` | `gemini` or `fake` (load tests and drills only) |
| `FAKE_LATENCY_MS`, `FAULT_RATE` | `800`, `0` | Fake provider latency and error rate |
| `RETRIEVER_K` | `4` | Titles retrieved per query |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | unset (tracing off) | OTel Collector endpoint |

## ☸️ Deploy to EKS
1. **Create the Terraform state bucket** (once per account):
   ```bash
   terraform -chdir=infra/terraform/bootstrap init
   terraform -chdir=infra/terraform/bootstrap apply
   ```
2. **Set your variables:** region, the IP CIDR allowed to reach the EKS API, and the budget alert email.
   ```bash
   cp infra/terraform/terraform.tfvars.example infra/terraform/terraform.tfvars
   ```
3. **Create the cluster.** `make up` provisions the VPC, EKS, ECR, the Secrets Manager entries and the GitHub OIDC role, then installs Argo CD. Argo CD installs everything else from `deploy/`.
   ```bash
   make up
   aws eks update-kubeconfig --name anime --region <region>
   ```
4. **Store the secrets.** External Secrets picks them up within a minute.
   ```bash
   aws secretsmanager put-secret-value --secret-id anime/llm \
     --secret-string '{"GOOGLE_API_KEY":"...","HF_TOKEN":"..."}'
   aws secretsmanager put-secret-value --secret-id anime/langfuse \
     --secret-string '{"LANGFUSE_PUBLIC_KEY":"...","LANGFUSE_SECRET_KEY":"..."}'
   aws secretsmanager put-secret-value --secret-id anime/alerting \
     --secret-string '{"DISCORD_WEBHOOK_URL":"..."}'
   ```
5. **Connect GitHub Actions to AWS:**
   ```bash
   gh variable set AWS_ROLE_ARN --body "$(terraform -chdir=infra/terraform output -raw github_actions_role_arn)"
   gh secret set HF_TOKEN        # used by the index stage of the image build
   ```
6. **Ship a change.** Push to `main`. CI then:
   1. runs lint and tests
   2. builds the api and ui images (including the 269-anime index check)
   3. scans them with Trivy
   4. pushes them to ECR and signs them with Cosign
   5. commits the new image digests to `deploy/`

   Argo CD syncs the change, and Argo Rollouts shifts traffic 10% → 50% → 100%. At each step it checks the canary: success rate must stay ≥ 99% and p95 within the latency SLO, otherwise the rollout aborts and traffic returns to the stable version. If the canary gets too little traffic to judge, the rollout pauses for a human instead of promoting.
7. **Verify** the deployment (next section), then run the load tests and drills.

## 🔍 Post-Deploy Verification
```bash
# App and rollout status
kubectl -n anime get rollout,pods,ingress
kubectl argo rollouts -n anime get rollout anime-api

# Public endpoint
ALB=$(kubectl -n anime get ingress anime -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
curl -X POST http://$ALB/recommend -H 'content-type: application/json' -d '{"query": "space pirates"}'

# Image signature (keyless, issued to this repo's CI)
IMAGE=$(yq .image.ref deploy/charts/anime-api/values.yaml)     # repo@sha256:...
cosign verify "$IMAGE" \
  --certificate-identity-regexp 'https://github.com/biabeogo147/Anime-Recommender/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

**Admin UIs** are not exposed publicly; open them through port-forwards:
```bash
make grafana   # dashboards: SLO overview, LLM latency/tokens/cost, rollouts; Tempo traces
make argocd    # sync status of every component
```

### Load tests & drills
| Command | What it shows |
|---|---|
| `make loadtest-baseline` | Real p50/p95 latency with Gemini at a low rate; sets the latency SLO threshold |
| `make loadtest-ramp` | Fake provider, 1 → 60 virtual users: max RPS within the SLO and pods scaling out |
| `make drill-canary` | A faulty release (`FAULT_RATE=0.2`) is rolled back automatically |
| `make drill-alert` | A 50% error rate triggers the fast-burn alert in Discord |

k6 results are saved to `docs/evidence/loadtest/`.

### Tear down
When idle, destroy everything (about 0.22 USD/hour while running). `make down` deletes the Ingresses first so the ALB is released, then runs `terraform destroy`.
```bash
make down
```

## 📊 Metrics Cheat-Sheet
The API exposes:
- `anime_http_requests_total{route,method,status}` (Counter)
- `anime_http_request_duration_seconds{route}` (Histogram, buckets 0.1 … 32s)
- `anime_http_requests_in_flight` (Gauge, the autoscaling signal)
- `anime_retrieval_duration_seconds`, `anime_llm_request_duration_seconds{model,outcome}` (Histograms)
- `anime_llm_tokens_total{model,type=input|output|reasoning}` (Counter)
- `anime_llm_cost_usd_total{model}` (Counter, estimated from `config/pricing.yaml`)
- `anime_index_info` (Info: content hash, document count, embedding model)

**SLOs** (28-day window, defined in `deploy/slo/`):
- **Availability:** 99.5% of `/recommend` requests succeed.
- **Latency:** 95% of `/recommend` requests finish under the threshold set by the baseline load test.

<details>
<summary>Prometheus/Grafana queries</summary>

```promql
# QPS
sum(rate(anime_http_requests_total{route="/recommend"}[1m]))

# P95 latency
histogram_quantile(0.95, sum(rate(anime_http_request_duration_seconds_bucket{route="/recommend"}[5m])) by (le))

# Error rate
sum(rate(anime_http_requests_total{route="/recommend",status=~"5.."}[5m]))
  / sum(rate(anime_http_requests_total{route="/recommend"}[5m]))

# Estimated cost per 1k requests
1000 * sum(rate(anime_llm_cost_usd_total[1h])) / sum(rate(anime_http_requests_total{route="/recommend",status="200"}[1h]))
```
</details>

## ⚙️ Scaling Defaults
| Setting | Value |
|---|---|
| API replicas (KEDA) | min 2, max 8 |
| Scale-out trigger | more than 4 in-flight requests per pod |
| Cooldown | 120 s |
| Nodes (Spot) | min 2, max 4 |

The LLM and embeddings are remote APIs, so the pods mostly wait on I/O. That is why scaling follows in-flight requests rather than CPU.

## 🛡️ Security Notes
- Containers run as non-root (UID 10001) with a read-only root filesystem.
- In-cluster controllers get AWS access through EKS Pod Identity.
- The EKS API endpoint is restricted to your IP CIDR; Grafana and Argo CD are reachable only by port-forward.
